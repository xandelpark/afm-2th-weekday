# album-ship — 앨범 택배목록 → 웨딩자동화시트 Y열 자동 체크

택배목록(예식일 + 신부이름)을 주면 구글시트 `웨딩자동화시트 / 고객정보` 에서
해당 신부 행을 찾아 **Y열 `앨범발송확인차문자전송 ( + 7일후 )` 체크박스를 클릭**한다.
체크하면 시트에 붙은 **Make 자동화**가 Z열(발송예정일 = 체크일+7일)을 채우고 문자를 예약한다.

## ⚠ 왜 API 로 안 쓰고 브라우저로 클릭하나

Sheets API 로 값을 쓰면 구글이 **'사람이 편집했다' 이벤트를 만들지 않는다.**
Make 는 그 편집 이벤트를 보고 동작하므로, API 로 Y만 켜면
**체크박스는 켜지지만 Make 가 돌지 않아 문자가 나가지 않는다.**

실제로 2026-09-02 에 API 로 켠 60건은 Y=TRUE 인데 Z가 끝까지 비어 있었고,
같은 행을 손으로 껐다 켜니 즉시 Z에 날짜가 찍혔다.

그래서 이 도구는 **로그인된 Chrome 에서 사람과 동일한 마우스 클릭**을 보낸다.
Z(발송예정일)는 **절대 우리가 쓰지 않는다.** 날짜만 적어 넣으면 문자는 안 나가는데
나간 것처럼 보이는 더 나쁜 상태가 되기 때문이다. Z는 Make 가 채운 것만 인정한다.

## 시트 구조 (고객정보)

| 열 | 내용 |
|----|------|
| A | 예식일 |
| D | 신부이름 |
| E | 신부연락처 |
| Y | 앨범발송확인차문자전송 ( + 7일후 ) ← **여기를 체크** |
| Z | 엘범발송문자 발송완료여부 |
| AB | 상품주소 |

## 최초 1회 설정

```bash
cp config.example.json config.json
# config.json 의 spreadsheet_id 에 구글시트 URL 의 /d/ 뒤 ID 를 넣는다
./.venv/bin/python albumship.py auth      # 시트 조회(매칭)용 구글 승인 1회
```

## 사용

```bash
# 0) 디버깅 Chrome 띄우기 — 창이 뜨면 구글 계정으로 로그인 (평소 Chrome 은 안 건드림)
./.venv/bin/python albumship.py browser

# 1) 미리보기 — 쓰기 없음. 어떤 행이 체크될지 먼저 확인
./.venv/bin/python albumship.py plan --list ~/Downloads/앨범택배목록_20260910.xlsx

# 2) 실제 클릭 (Make 트리거 → 7일 뒤 문자)
./.venv/bin/python albumship.py apply --list ~/Downloads/앨범택배목록_20260910.xlsx --yes
```

`browser` 로 띄운 창은 **열어두는 게 좋다.** 닫으면 로그인이 풀려 다시 로그인해야 한다.
Chrome 136+ 는 기본 프로필에 원격 디버깅을 허용하지 않아, 쿠키만 복사한 별도 프로필로 띄운다.

구글시트 없이 다운로드본으로 매칭만 검증하려면 `--xlsx ~/Downloads/웨딩자동화시트.xlsx` 를 붙인다.

## 입력 형식

`--list` 는 아래를 모두 받는다.

- `.xlsx` — `예식일`, `신부이름` 헤더가 있는 시트 (탭 여러 개도 전부 읽음). `전화번호`, `상품주소` 는 선택
- `.csv` / `.tsv` — 같은 헤더
- `.txt` — 헤더 없는 자유형식도 가능: `260509.안윤진`, `2026-05-09 안윤진 010-1234-5678`

## 안전장치

- `plan` 은 절대 쓰지 않는다. `apply` 는 `--yes` 없이는 실행되지 않는다.
- **Y열 외에는 아무 것도 쓰지 않는다.** Z는 Make 가 채우는 값이다.
- 클릭 후 행마다 Z가 채워졌는지 확인하고, 안 된 건은 30초 뒤 재확인한 다음 그래도 없으면 보고한다.
- **이미 Y가 체크된 행은 건너뛴다** — 중복 문자 방지.
- 미매칭·중복 항목이 하나라도 있으면 `apply` 가 멈춘다. 나머지만 처리하려면 `--allow-partial`.
- 매칭 우선순위: `예식일+이름` → `예식일+이름(끝자리 숫자 제거)` → `전화번호`.
  두 번째·세 번째로 잡힌 건은 `⚠...매칭 — 확인 필요` 로 표시된다.
- 목록과 시트의 전화번호가 다르면 `⚠전화번호 불일치` 로 표시된다.

`token.json` 과 `config.json` 은 `.gitignore` 에 있다.

## 처리 이력

| 목록 | 체크일 | 건수 | 시트 Y=TRUE | 문자 발송예정 |
|---|---|---|---|---|
| 앨범택배목록_20260820 | 2026-09-02 | 30 (권희주 미매칭 1건 제외) | 36 → 66 | 2026-09-09 |
| 앨범택배목록_20260902 | 2026-09-02 | 30 | 66 → 96 | 2026-09-09 |
| 앨범택배목록_20260910 | 2026-09-10 | 28 | 96 → 124 | 2026-09-17 (Z 기록 확인 28/28) |

### 해결됨 — Z열 미기록 원인

2026-09-09 발송 예정이던 60건(8/20·9/2 목록)의 **Z열(엘범발송문자 발송완료여부)이 9/10 기준 전부 비어 있다.**
시트 전체에는 Z가 채워진 행이 427건 있으므로(`2025-12-16`, `2026-06-08전송완료` 형식) 평소엔 기록이 남는다는 뜻이다.

Y 체크 자체는 28/28·30/30 모두 시트에서 되읽어 `TRUE` 확인됐고, Y열은 데이터유효성 `BOOLEAN` 인 진짜 체크박스다.
따라서 **체크 이후 단계(발송 자동화)가 돌지 않았을 가능성**이 있다. 다만 Z를 자동화가 채우는지 사람이 적는지는 미확정이므로,
**원인은 Sheets API 쓰기가 Make 의 편집 트리거를 발동시키지 않는 것이었다.**
2026-09-10 에 브라우저 클릭 방식으로 바꾼 뒤 9/10 배치 28건은 전부 Z=2026-09-17 이 정상 기록됐다.
8/20·9/2 배치 60건은 발송일(9/9)이 지나 그대로 두기로 했다.
