# 문제 될 것들 — 점검표

2026-11-02 갱신. **설계가 측면 단일 카메라로 바뀌면서 위험이 대부분 사라졌다.**

---

## 사라진 것 — 멀티캠을 버리면서 같이 없어짐

이전 설계(폰을 역V로 접어 네트 중앙에 거치, 앞·뒤 카메라 동시 녹화)의 미해결 항목들:

| 항목 | 왜 사라졌나 |
|---|---|
| 두 `AVCaptureMovieFileOutput` 동시 사용 가능? | 카메라 하나 · 출력 하나 |
| 울트라와이드 + 전면 조합이 기기에서 열려 있나? | 전면을 안 쓴다 |
| `hardwareCost ≤ 1.0` 예산 | 멀티캠 세션이 아니다 |
| 앞 카메라가 둘(외부/내부 언더디스플레이) 중 어느 쪽을 집나 | 뒷면만 쓴다 |
| 면별 회전 — 역V면 한쪽이 뒤집힘 | 한 면이라 회전 하나 |
| 접힌 폰을 잡을 거치대가 없음 (3D 프린트 필요) | **일반 폰 클램프로 된다** |
| 네트 중앙은 공 맞는 자리 | 코트 옆 9 m — 공 경로 밖 |
| 앞/뒤 카메라 화질 차이 | 단일 48MP. 남은 차이는 가까운/먼 코트(약 2.5배) |

코드도 줄었다: `CaptureEngine` 463줄 → **334줄**, 멀티캠 진단 파일(113줄) 삭제.

## A. 첫 빌드에서 막힐 것 — 이름이 틀렸을 수 있는 API

iOS SDK 없이 썼으니 컴파일을 못 했다. 아래가 틀렸을 가능성이 있는 지점이고,
Xcode가 **에러로 정확히 어디가 틀렸는지 알려준다.** 전부 한 줄짜리 수정이다.

| 심볼 | 어디 | 근거 수준 |
|---|---|---|
| `conn.isVideoRotationAngleSupported` / `videoRotationAngle` | CaptureEngine | iOS 17+ 신 API. 구버전 경로를 같이 뒀다 |
| `AVErrorRecordingSuccessfullyFinishedKey` | CaptureEngine | 불확실 — 없으면 그 한 줄만 지우면 된다 |
| `AVError.mediaServicesWereReset` | CaptureEngine | 확실한 편 |
| `output.minFreeDiskSpaceLimit` | CaptureEngine | 확실한 편 |
| `volumeAvailableCapacityForImportantUsageKey` | Preflight | 확실한 편 |
| `.persistentSystemOverlays(.hidden)` | ContentView | iOS 16+ |

단일 카메라 세션(`AVCaptureSession` + `AVCaptureDeviceInput` +
`AVCaptureMovieFileOutput` + `AVCaptureVideoPreviewLayer`)은 표준 경로라
멀티캠 때보다 틀릴 여지가 훨씬 적다.

## B. 아직 모르는 것

### B-1. 4K 가 울트라와이드에서 되나

`canSetSessionPreset(.hd4K3840x2160)` 를 물어보고 안 되면 1080p → 720p 로 내려간다.
울트라와이드는 메인보다 지원 포맷이 적을 수 있다.

- **확인:** 상단에 "렌즈 · 해상도" 가 표시된다.
- **1080p 로 내려가면**: 좌우 반 크롭이 코트당 960×1080 이 된다. 보기엔 되지만
  나중에 코트별로 따로 쓰려면 아쉽다.

### B-2. 울트라와이드의 왜곡

13 mm 는 가장자리가 늘어난다. 코트 양 끝(베이스라인)이 프레임 끝에 오므로
**거기서 가장 심하다.** 라인 판정에는 못 쓴다. 랠리 흐름과 점수 확인용이다.

### B-3. 펜스 그물이 화면에 들어오나

펜스에 바짝 붙이면 그물이 흐려져 거의 안 보이지만 안개처럼 남을 수 있다.
펜스 안쪽에 삼각대를 세우거나 펜스 위로 넘겨 보는 쪽이 깨끗하다.

## C. 운용 — 고쳐둔 것

| 문제 | 어떻게 했나 |
|---|---|
| 전화·제어센터·다른 앱이 카메라를 가져감 | 중단 5종을 받아 이유를 띄우고 파일을 안전하게 닫는다 |
| 앱이 백그라운드로 감 | iOS가 뺏기 전에 우리가 먼저 마무리 |
| 세션 런타임 오류 | 미디어 서비스 재설정이면 자동 재시작 |
| 과열 | `serious` 경고 · `critical` 에서 스스로 마무리 |
| 디스크가 차서 파일이 깨짐 | `minFreeDiskSpaceLimit` 300 MB |
| 공간·배터리가 경기를 못 버팀 | 시작 전 점검에서 남은 분 수 계산 |
| 거치 중 오탭 | 득점 탭 **기본 잠김** |
| 거치가 거꾸로 | 180° 뒤집기 버튼 |
| 9 m 밖에서 각도를 맞출 기준이 없음 | **화면 안내선** — 네트 세로선 + 베이스라인 한계선 |
| 포인트 기록이 영상 폴더를 못 찾음 | 엔진이 폴더를 들고 있다가 넘긴다 |
| 녹화 전에 센 점이 영상 0초를 가리킴 | "녹화전" 으로 적고 CSV 초 칸을 비운다 |
| 경기 형식을 바꾸면 기록이 날아감 | 점이 있으면 변경을 되돌린다 |
| 설정 중 화면 멈춤 | 세션 조작을 전용 직렬 큐로 |

## D. 운용 — 아직 답이 없는 것

### D-1. 9 m 떨어진 폰을 어떻게 조작하나 ← 새로 생긴 문제

이전 설계는 네트 중앙이라 손이 닿았다. 측면 펜스는 **경기 중에 못 간다.**

- **레슨·연습**에서는 코치가 펜스 옆에 서 있으니 그대로 쓸 수 있다
  (매장 레슨이 주 용도면 문제없다).
- **경기**에서는 점수를 실시간으로 못 넣는다. 녹화만 하고
  끝나고 영상 보면서 넣거나, 점수 없이 영상만 쓰는 쪽이다.
- 두 번째 기기에서 조작하는 방법은 아직 없다.

### D-2. 배터리와 발열이 충돌한다

2시간에 약 72%. 보조배터리를 연결하면 발열이 올라가 과열 중단 위험이 커진다.
세트 사이에만 충전하거나 1080p 로 내려 찍는다. **한 경기 찍어봐야 결론이 난다.**

### D-3. 저장 공간

4K 2시간 약 17.6 GB. 경기 몇 번이면 금방 찬다 — 끝나고 바로 빼는 습관이 필요하다.

## E. 아직 안 만든 것

- **실시간 중계** (RTMP). 녹화가 실기기에서 확인된 다음에 붙인다.
- 좌우 반씩 잘라 코트별로 보여주는 화면
- 경기 형식 고르는 화면 · 선수 이름 입력
- 점수 자동 추적

## 다음에 할 일

3. 한 경기 촬영 → D-2 결론.
4. D-1 을 어떻게 할지 결정 (레슨 전용으로 둘지, 원격 조작을 만들지).
5. 그 다음에 중계.
