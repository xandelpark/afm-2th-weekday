# 코워크 (worktime)

프리랜서 타임시트. 설치 없이 브라우저만으로 동작한다.
작업 시작/종료 버튼이 매일 눌리는지와, 코어타임(5시간)을 채우는지를 본다.

> 이름과 문구를 일부러 부드럽게 잡았다. 감시 도구가 아니라 '함께 일하는 시간을 기록하는' 도구로 읽히게 하기 위해서다.
> `출근/퇴근` 대신 `작업 시작/종료`, `미출근` 대신 `기록 없음`을 쓴다.

## 실행

```bash
npm install
node server.js     # http://localhost:3011
```

`.env` 필수 값 — `DATABASE_URL` `JWT_SECRET` `ADMIN_PASSWORD` `VAPID_PUBLIC` `VAPID_PRIVATE`
(하나라도 없으면 서버가 뜨지 않는다. `.env`는 git에 올리지 않는다.)

DB 초기화는 `schema.sql`을 Supabase에 한 번 실행.

## 동작 방식

로그인한 뒤 **작업 시작**을 누르면 그때가 시작 시각, **작업 종료**를 누르면 그때가 종료 시각이다.
로그인만으로는 시작 처리되지 않는다 — 버튼을 눌렀는지가 확인 대상이기 때문이다.

핵심 지표는 **코어타임(10:00~15:00, 5시간) 충족 여부**다.
작업 시작~종료 구간과 코어타임이 겹치는 시간을 재서 5시간을 채웠는지 본다.
예를 들어 09:30 시작 · 16:00 종료면 충족(○), 11:00 시작 · 14:00 종료면 3시간이라 부족(△).

작업 종료를 누르지 않은 채 날이 바뀌면 **종료 기록 없음(✕)**으로 남는다.
끝난 시각을 임의로 지어내지 않으므로 그날 작업시간은 0으로 잡히고, 작가 화면에 빨갛게 드러난다.
작업 가능 종료시각(기본 20:00)이 지나도 안 눌렀으면 알림이 한 번 간다.

근무일·코어타임 계산은 모두 **KST(UTC+9)** 기준이다.

### 한계

버튼을 누른 시각만 믿는 방식이라, 실제로 자리에 있었는지는 확인하지 않는다.
누르고 나갔다 와도 기록상으로는 근무로 남는다.

## 관리자 화면

| 탭 | 내용 |
|---|---|
| 오늘 현황 | 지금 누가 작업 중인지, 오늘 시작/종료 시각과 코어타임 충족 여부 |
| 월간 기록 | **팀 전체 매트릭스** — 행=사람, 열=1~31일. 이름을 누르면 그 사람 달력으로 |
| 리터쳐 관리 | 추가 · 접속 코드 재발급 · 활성/비활성 |
| 시간 설정 | 작업 가능·코어타임 시간대, 알림 on/off |

**월간 기록**은 한 달치가 한 화면에 들어온다. 셀에 마우스를 올리면 그날 시작·종료 시각과 작업시간이 뜨고,
오른쪽에 작업일수 · 충족일수 · 총 작업시간이 붙는다.

**사람별 달력**은 실제 월간 달력 모양으로, 각 날짜에
`09:30~16:00` / `6시간 30분` / 미달이면 `코어 60%`가 표시된다.
하루에 여러 번 나눠 작업했으면 `2회 나눠 작업`으로 표시되고, 달력 아래에 구간이 따로 나온다.

## 알림

코어타임 종료 시각과, 작업 종료를 안 누른 경우에 알린다.
**설치·권한·OS 설정 없이 동작하는 화면 알람이 기본**이다.

1. **모달** — 화면 한가운데 크게 뜬다
2. **소리** — 음원 파일 없이 웹오디오로 삐 소리 3번
3. **탭 제목 깜빡임** — 다른 탭을 보고 있어도 `🔔 …`가 번갈아 뜬다

**'확인'을 누를 때까지 사라지지 않는다.** 발생 시점에 닫아버리면 한 번 놓쳤을 때
새로고침해도 되살릴 방법이 없어서다. 모달 바깥을 클릭해도 닫히지 않는다.
백그라운드 탭은 브라우저가 타이머를 늦추므로, 창으로 돌아오는 순간에도 다시 확인한다.

브라우저는 사용자가 페이지를 한 번 건드리기 전엔 소리를 막는다.
그래서 첫 클릭에 오디오를 깨우고, 그전에 알람이 떴다면 그 클릭에서 소리가 난다.

알림 권한이 이미 있으면 OS 알림도 **같이** 띄운다(브라우저를 닫아도 옴). 되면 좋고, 안 돼도 위 3가지로 충분하다.

> 웹 푸시는 HTTPS(또는 localhost)에서만 동작하고, **시크릿 모드에서는 크롬이 Push API를 막는다.**

## API

인증은 JWT. 작가(`admin`)와 리터쳐(`worker`) 토큰의 권한이 분리돼 있다.

| 경로 | 권한 | 설명 |
|---|---|---|
| `POST /api/login` | — | 접속 코드 로그인 (시작 처리 아님) |
| `POST /api/admin/login` | — | 작가 로그인 |
| `POST /api/checkin` | worker | 작업 시작 |
| `POST /api/checkout` | worker | 작업 종료 |
| `GET /api/me` | worker | 본인 오늘 기록 |
| `GET /api/admin/overview?date=` | admin | 팀 현황 |
| `GET /api/admin/month?month=` | admin | 월별 집계 |
| `POST /api/admin/workers` | admin | 리터쳐 추가(코드 발급) |
| `POST /api/admin/workers/reset` | admin | 코드 재발급 |
| `POST /api/admin/workers/toggle` | admin | 활성/비활성 |
| `POST /api/admin/policy` | admin | 시간 설정 변경 |
| `POST /api/push/subscribe` | worker | 푸시 구독 등록 |
| `POST /api/push/test` | worker | 알림 테스트 발송 |

## 보안 설계

참고한 기존 앱(Team HQ)에 있던 문제를 의도적으로 피했다.

- 접속 코드는 **bcrypt 해시로만** 저장한다. 발급 직후 1회만 화면에 보이고 이후 복구 불가(재발급만 가능).
  작가 화면에는 `8••••4` 형태의 힌트만 남는다.
- 작가 비밀번호는 **서버 `.env`에만** 둔다. 클라이언트 코드에 넣지 않는다.
- 모든 데이터 API는 JWT를 검사한다. 리터쳐 토큰으로 작가 API를 부르면 401.
- 저장은 **행 단위**라 두 사람이 동시에 써도 서로의 기록을 덮어쓰지 않는다.

## 배포 시 반드시 할 것

1. `JWT_SECRET`을 임의의 긴 문자열로 교체
2. `ADMIN_PASSWORD`를 실제 비밀번호로 교체
3. HTTPS 적용 (웹 푸시 필수 조건)
