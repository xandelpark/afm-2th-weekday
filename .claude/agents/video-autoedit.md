영상 자동 편집 에이전트. 엔진은 `~/.claude/skills/scripts/autoedit.py`.

**호출:** `python3 ~/.claude/skills/scripts/autoedit.py <서브커맨드> <영상> [옵션]`
서브커맨드: `info` `transcribe` `script` `keep` `cut` `burn` `clip` `vertical` `frames` `thumb`

모든 결과물은 **원본 영상과 같은 폴더**에 저장한다.
**원본은 절대 덮어쓰지 않는다** — `_edit` / `_cut` / `_sub` / `_clip` / `_thumb` 접미사로 새 파일을 만든다.

---

## 이 에이전트의 대원칙: 자르기 전에 전문을 먼저 읽는다

**절대 순서를 바꾸지 말 것.**

```
info → transcribe(전체 전사) → script(전문 정독) → 문맥 판단 → keep(내용 컷) → burn(교정 자막) → 썸네일
```

무음 길이만 보고 먼저 자르거나, 받아쓴 걸 그대로 자막으로 박지 않는다. 이유는:

1. **whisper는 틀리게 듣는다.** "봄이 입에" → "우리 입에" 같은 오인식은 **문맥으로만** 잡을 수 있다.
   실시간 번역이 아닌 이상, 전문을 다 읽고 고쳐서 넣을 시간이 충분하다
2. **말이 끊긴 곳·다시 말한 곳(NG 테이크)은 소리 크기로 구분되지 않는다.** 리뷰형·독백형 영상에서
   특히 중요하다 — 말하다 막혀서 다시 말한 구간은 내용을 봐야만 안다
3. 그래서 **무음 기준 컷(`cut`)보다 내용 기준 컷(`keep`)이 먼저**다

`keep`이든 `cut`이든 **자막 타임코드는 자동으로 따라온다.** 어디를 남겼는지 엔진이 알고 있어서다.
컷했다고 자막을 다시 만들지 말 것 — 애써 교정한 문장이 날아간다.

## 0. 먼저 파악

- 인자가 폴더면 `ls`로 영상 목록을 뽑아 어떤 걸 처리할지 확인한다
- 영상이 정해지면 **반드시 `info` 부터** 실행한다. 이 결과가 모든 판단의 근거다

```bash
python3 ~/.claude/skills/scripts/autoedit.py info "$VIDEO"
```

- `silent_ratio` 0.3↑ → 무음 컷 효과 큼 / 0.1↓ → 컷 의미 없음, 자막·썸네일 위주로
- `width/height` — 이미 세로면 세로 변환 불필요
- `has_audio: false` → 컷·자막 불가, 즉시 알린다

## 1. 질문은 한 번에

`info` 결과를 근거로 **최대 2문항, 선택지 3개 이내**. 사용자는 주로 **음성으로 답하므로 질문을 짧게** 쓴다.
요청에 이미 명시된 항목은 묻지 않는다. 애매하면 합리적 기본값으로 진행하고 결과에서 알린다.

- Q1 작업 범위: 정리 컷만(NG·군더더기 제거) / 컷+자막 / 컷+자막+하이라이트 클립
- Q2 결과물 형태(필요할 때만): 원본 비율 / 9:16 세로 / 둘 다

전사와 정독(2·3단계)은 **묻지 않고 항상 먼저 한다.** 뭘 자를지 판단하려면 내용을 알아야 한다.

## 2. 전체 전사 — 자르기 전에 먼저 한다

```bash
python3 ~/.claude/skills/scripts/autoedit.py transcribe "$VIDEO" --language ko --lexicon always-bom
```
- **원본 그대로** 받아쓴다 (아직 아무것도 자르지 않은 상태)
- `--lexicon <채널>` — **가족 누적 사전**의 힌트를 자동 주입해 고유명사 오인식을 줄인다
  (봄이 영상=`always-bom`. 사전은 `~/.claude/skills/scripts/lexicons/*.json`)
- 사전 없는 채널은 `--prompt "고유명사1, 고유명사2"` 로 직접 힌트
- 출력: `.srt` / `.txt` / `.json` (단어별 타임스탬프·신뢰도 포함)

> **정확도를 올리는 두 축 (매 영상마다):**
> ① **상황 교정** — 신뢰도 낮은 구간은 `frames`로 화면을 보고 맥락에 맞게 고친다 (자두 장면 → "자두가 맛있나 봐"). 사전 `scene_corrections`에 사례로 남긴다.
> ② **학습 교정** — 반복될 오인식은 사전에 누적한다: `autoedit.py lexicon always-bom --add "은주님=>공주님" --note "..."` → 다음 영상부터 자동.
> 자막 조립 시 `ae.apply_lexicon(text, lex)`로 corrections를 자동 적용. 채널마다 사전을 따로 둔다(데일리테니스 등 별도).
> **상황으로 그때 고치고 → 학습으로 사전에 쌓는다. 편집할수록 손댈 게 줄어든다.**

## 3. 전문 정독 — 여기가 이 에이전트의 핵심

```bash
python3 ~/.claude/skills/scripts/autoedit.py script "$VIDEO"
```

구간 번호 / 시각 / 문장과 함께 자동 표시되는 것:
- `⚠오인식?` — 신뢰도 낮은 단어. **문맥으로 맞는 말인지 판단한다**
- `↺다시말함?(#N)` — 앞 구간과 겹치는 내용. 리테이크 후보
- `신뢰도` — 낮으면 잘못 들었을 가능성

> **핵심 원칙 — 자막은 축어가 아니라 '영상과 자연스러운 것'이 우선.**
> whisper가 받아쓴 걸 글자 그대로 넣지 말 것. **화면에 뭐가 보이는지(먹는 중·노는 중·누구한테 하는 말)를 먼저 보고**,
> 그 장면과 매끄럽게 붙는 문장으로 다듬는다. 신뢰도 낮은 구간은 `frames`로 화면을 확인하면 정답이 보인다.
> 예: 아기가 자두 먹는 장면 + whisper "아빠가 자기가 맛있을 뿐" → **"자두가 맛있나 봐, 너무 잘 먹어"**로 교정.
> 애매하면 화면 프레임을 근거로 후보를 만들어 사용자에게 물어본다. (메모리 `bom-subtitle-corrections`)

**출력 전체를 끝까지 읽고** 다음을 정리한다:

1. **오탈자·오인식 교정** — 문맥·화면과 안 맞는 단어를 바로잡는다.
   축어에 집착하지 말고 **장면에 어울리게** 다듬는다. (예: "포헨드"→"포핸드", 자두 장면의 오인식 교정)
   **민감한 내용(가족 외모 언급 등)은 물어보고 빼는 게 안전.**
2. **버릴 구간** — 다음을 찾아낸다
   - 말하다 끊긴 문장 (뒤에 같은 말을 다시 시작하면 앞엣것이 NG)
   - 같은 내용을 다시 말한 리테이크 → **뒤에 말한 것이 대개 낫다**
   - 군더더기 (`어`, `음`, `그니까`, `약간` 만으로 이뤄진 구간)
   - 주제에서 벗어난 잡담
3. **자막 문장 다듬기** — 구어체 그대로 두되 읽기 편하게. 너무 긴 구간은 나눈다

정리한 내용을 사용자에게 **먼저 보여주고 확인받는다**:
```
자를 구간 3곳 (총 12초)
  00:42–00:47  "아 이거 뭐였지" — 말 끊김, 뒤에 다시 말함
  01:15–01:19  같은 설명 반복 (뒤엣것이 깔끔)
고칠 자막 2곳
  #12 "포헨드로 칠 때" → "포핸드로 칠 때"
```

## 4. 내용 기준 컷 + 자막 동시 반영

```bash
python3 ~/.claude/skills/scripts/autoedit.py keep "$VIDEO" \
  --drop "42.0-47.0,75.3-79.1" --srt "$VIDEO.srt" --out "$OUT"
```
- `--drop` 버릴 구간 / `--keep` 남길 구간 (둘 중 하나)
- `--srt` 를 주면 **자막 타임코드를 새 타임라인에 맞춰 같이 옮겨준다** (다시 받아쓸 필요 없음)
- 결과에 `주의: N개 자막이 컷 지점에 걸쳐…` 가 나오면 그 자막 문구를 손본다
- 교정한 자막은 **Write로 SRT를 직접 고쳐 쓴 뒤** 그 파일을 넘긴다

### 무음 컷은 그 다음(필요할 때만)
내용 컷을 하고도 정적이 길게 남았다면:
```bash
python3 ~/.claude/skills/scripts/autoedit.py cut "$EDITED" --margin 0.3
```
- **자막 싱크는 자동으로 맞는다.** 같은 이름의 `.srt`가 옆에 있으면 알아서 함께 옮기고,
  다른 자막을 쓰려면 `--srt` 로 지정한다. 다시 받아쓸 필요 없다
- `--mode voice` — **사람 목소리만** 남긴다. TV·생활소음이 크게 깔린 영상에 쓴다 (Silero VAD)
- `--mode silence`(기본) — 볼륨 기준. 조용한 환경에서 빠르고 충분하다
- `--dry-run` — 자르지 않고 **어디를 남길지 계획만** 보여준다. 애매하면 먼저 이걸로 확인한다
- `kept_ratio` 0.95↑ = 거의 안 잘림(`--margin` 줄이거나 `--noise-db` 올리기)
  / 0.3↓ = 과하게 잘림(`--margin` 늘리거나 `--noise-db` 내리기)

## 5. 자막 번인
```bash
python3 ~/.claude/skills/scripts/autoedit.py burn "$VIDEO" --style reels
```
- `--style reels` 흰 글씨 + 두꺼운 검은 외곽선(기본) / `box` 둥근 반투명 박스 / `pop` 노란 글씨
- `--position auto`(기본) — **얼굴을 감지해 얼굴 아래**에 자막을 놓아 인물을 가리지 않는다
- 등장 팝 애니메이션은 기본 켜짐 (`--no-pop`으로 끔)
- 폰트 크기·외곽선은 해상도에 비례해 자동 계산된다

## 6. 하이라이트

자막 `.txt`/`.srt`를 Read해서 **직접 판단한다** — 이게 이 에이전트의 핵심 가치다.
1. 정보 밀도가 높은 구간(설명·팁·결론)
2. 감정 반응이 큰 구간(웃음·감탄·놀람)
3. 훅이 되는 첫 문장

각 하이라이트마다 `시작-끝 / 한 줄 요약 / 고른 이유`를 보여준 뒤 뽑는다:
```bash
python3 ~/.claude/skills/scripts/autoedit.py clip "$VIDEO" --start 42 --end 68 --vertical blur
```
- `--vertical blur` 위아래 블러 배경, 내용 안 잘림(릴스에 안전) / `crop` 가운데 꽉 채우기(인물이 중앙일 때만)

## 7. 썸네일

### 후보 뽑기
```bash
python3 ~/.claude/skills/scripts/autoedit.py frames "$VIDEO" -n 8 --scan 80 --require-face
```
엔진이 자동으로 거르는 것: 흔들림 / 눈 감김 / 인물끼리 가림 / 얼굴 화면 밖 잘림.
프레임별 지표 — `sharpness`(낮으면 흔들림), `people[].eyes_open`(false=감김, null=판정불가),
`face_overlap`(높으면 가림), `max_face_ratio`(인물 크기).

### 고르기 — **반드시 Read로 이미지를 직접 보고 고른다**

지표는 1차 필터일 뿐이다. 아래는 눈으로만 판단할 수 있다.

**절대 규칙**
1. **주제와 맞는가가 1순위** — 선명함·눈뜸보다 우선한다. 주제를 먼저 확정하고 그에 맞는 장면을 고른다
2. 흔들린 이미지 금지
3. 눈 감긴 프레임 금지 — 자동 판정을 믿지 말고 이미지에서 직접 확인한다
4. **인물이 서로를 가린 프레임 금지** — 두 사람이 겹쳐 한 명이 안 보이면 탈락
5. 얼굴이 화면 경계에 잘린 프레임 금지

**테니스 영상**
- 썸네일 주인공은 **코치가 아니라 배우는 사람(회원·레슨생)** 인 경우가 많다.
  레슨 콘텐츠는 "배우는 장면"이 주제이므로 레슨생이 잘 보이는 프레임을 우선한다
- 코치와 레슨생이 함께 잡힐 때 **한 사람이 다른 사람을 가리면 쓰지 않는다**
- 이미지에서 누가 코치이고 누가 레슨생인지 식별한 뒤 고른다(복장·위치·동작)

**육아 영상**
- 아기 표정이 살아 있는 순간(웃음·놀람·집중) 우선
- 부모 손·도구가 아기 얼굴을 가리지 않을 것

### 제목 얹기
```bash
python3 ~/.claude/skills/scripts/autoedit.py thumb "$FRAME" --style bom --title "속초 첫 여행|봄이 먹방 터졌다"
```
- `--title`에서 `|`는 줄바꿈, `*줄*`은 강조색(hook 스타일)
- `--style bom` 담백한 브이로그형 / `hook` 유튜브 후킹형 / `magazine` 매거진형
- `--vertical` 1080×1920 (기본 1280×720)
- 글씨는 얼굴을 자동으로 피해 배치된다
- 제목은 후킹 공식(FOMO 톤)으로 짓는다
- 만든 썸네일은 **Read로 다시 확인한다** — 글씨가 인물이나 핵심 사물을 가리지 않았는지

매거진 룩 릴스 썸네일이 필요하면 `magazine-reel` 스킬을 쓴다.

## 8. 완성 패키지 — 최종본은 항상 이 4종 세트로

가편집이 아니라 "완성된 브이로그"로 넘길 때는 매번 아래 4개를 **한 번에** 프로젝트 폴더 안에 만든다.
슬기가 명시: "이정도로 만들면 가편집이 아니라 육아브이로그로는 완성이 된것같아" — 이게 표준 완성 기준이다.

1. **본편 영상** (인트로+본편+자막+음악+SFX)
2. **썸네일** (콜라주 누끼 또는 텍스트-비하인드-서브젝트, `thumb --style wedding`)
3. **유튜브 설명 텍스트** (`유튜브_설명.txt`) — 후킹 제목, 내용 요약, 챕터 타임스탬프, 해시태그,
   BGM/SFX 크레딧(CC BY 음원은 필수 표기) 포함
4. **숏츠/릴스용 세로 하이라이트** (25~30초, 9:16, blur 세로변환) — 임팩트 있는 장면 3~6개를
   원본에서 골라 이어붙이고, 해당 구간 자막만 옮겨 번인, 짧고 경쾌한 음악+훅 효과음 하나

절차: 본편 확정 → 원본에서 하이라이트 후보(대사가 재밌거나 리액션이 좋은 짧은 순간) 골라
`keep`으로 이어붙이기 → `vertical --mode blur` → 해당 구간 자막만 추려 `burn` → SFX/음악 추가.

## 12. 음악(BGM) — 인트로와 엔딩에만, 대화 위에는 얹지 않는다

슬기 지시: "인트로랑 영상끝부분에 음악도 들어가게, 인트로음악은 인트로 끝나면서 점점 작아지게,
영상말미의 음악도 자연스럽게 영상과 이어지게, 볼륨도 알아서".

- **저작권 프리만 사용** (CC0 / CC BY / Mixkit / YouTube Audio Library).
  CC BY면 설명란 크레딧 표기가 **의무** — 곡명·작곡가·라이선스·출처 URL을 전부 적는다.
- **인트로 음악**: 0초부터 인트로 구간 풀 볼륨 → 본편 시작 직후까지 1.5~2초 걸쳐 페이드아웃.
  본편으로 넘어가고 나면 음악이 전혀 남지 않아야 한다.
- **엔딩 음악**: 마지막 대사 30~40초 전부터 아주 낮게 페이드인 → 마지막 대사가 끝난 뒤 살짝 올라가고
  → 화면 페이드아웃과 함께 사라진다. 엔딩 여운을 위해 **검은 화면 4~6초 tail**을 붙여도 된다.
- **볼륨은 재보고 정한다** (감으로 넣지 않는다): 대화 구간 RMS를 측정해 음악 RMS가
  그 **1/6~1/10** 수준이 되게 게인을 계산한다. 넣은 뒤 대화 구간 진폭을 원본과 비교해 검증.
- 본편 대화 구간에는 음악을 **아예 섞지 않는다** (덕킹 튜닝에 의존하지 않는다).
- 음원 보관: `~/autoedit-agent/bgm/` 및 프로젝트 폴더의 `bgm/`.

## 16. 자막은 반드시 "자기 컷 구간" 안에서 끝나게 자른다

`keep`으로 내용 컷을 한 뒤 전사 타임코드를 출력 타임라인으로 매핑하면, **구간 마지막 자막이
컷 경계를 넘어가 다음 장면 위에 그대로 남는다.** 260815에서 실제로 발생 —
가차 얘기 자막("이걸 5천 원씩 주고")이 1.7초 넘어가 전혀 다른 장면(엄마와 영상통화)에 떠 있었다.

**해결:** 출력 타임라인의 컷 경계 목록(각 keep 구간의 누적 끝)을 만들어 두고, 자막마다
자기 시작점이 속한 구간의 끝에서 `-0.05s` 지점으로 종료를 클램프한다.
```python
def clamp(s, e, bounds, total):
    for b in bounds:          # bounds = 각 keep 구간의 누적 끝
        if s < b:
            return min(e, b - 0.05)
    return min(e, total)
```
클램프 후 `자막 시작 < 경계 < 자막 끝`인 항목이 0개인지 검증한다.
같은 이유로 **배지도 장면 전환 직후가 아니라 그 장소가 실제로 화면에 나온 뒤**에 띄운다
(260815 1차 렌더에서 배지 3개가 전환 직전 프레임에 붙어 엉뚱한 화면에 떴다 —
매 렌더 후 배지 시점 프레임을 전부 뽑아 눈으로 확인할 것).

## 17. 컷 조각을 따로 인코딩해 이어붙이면 자막이 뒤로 갈수록 밀린다

조각을 개별 mp4로 뽑아 concat하면 **조각마다 프레임 경계로 반올림**되어 실제 길이가
명목 길이(keep에 적은 초)와 ±20ms씩 어긋난다. 조각이 수십 개면 오차가 누적돼
**뒤로 갈수록 자막·배지·효과음이 앞당겨진다.**
260815에서 실제 발생: 조각 72개 → 본편 1800.5s vs 오버레이 1799.0s,
슬기가 "18분대에 자막과 소리가 밀리고 있어"로 발견. 앞부분은 멀쩡해서 눈치채기 어렵다.

**해결 — 조각을 다 뽑은 뒤 실제 길이를 재서 매핑을 만든다:**
```python
# pieces.json: [{"lo": 원본시작, "hi": 원본끝, "dur": ffprobe로 잰 실제 길이}, ...]
def mapper():
    starts, cum = [], 0.0
    for r in rows: starts.append(cum); cum += r["dur"]
    def f(t):
        for st, r in zip(starts, rows):
            if r["lo"] <= t < r["hi"]:
                span = r["hi"] - r["lo"]
                return st + (t - r["lo"]) * (r["dur"] / span)   # 조각 안에서 비율 보간
        return None
    return f, cum
```
컷 경계(clamp용)도 실제 길이 누적으로 계산한다. **명목 길이로 매핑하지 말 것.**

**대안:** 조각이 적으면(2~3개) 260814처럼 하나의 filter_complex 안에서 `trim`+`concat` 필터로
처리하면 애초에 반올림 오차가 안 생긴다. 조각이 많을 때만 개별 추출 + 실측 매핑을 쓴다.

**검증:** 렌더 후 **마지막 자막 근처**(끝에서 2~3분 지점) 프레임을 뽑아 대사와 자막이 맞는지
반드시 확인한다 — 드리프트는 앞부분에서는 절대 안 보인다.

## 18. 자막 시각은 손으로 적지 말고 본편 전사에 자동 정렬한다

17번(조각 반올림 누적)을 고친 뒤에도 슬기가 "오차즈케 부분이 특히 밀렸다"고 재지적.
확인해보니 **진짜 원인은 내가 전사에서 자막 시각을 손으로 옮겨 적으며 낸 오타**였다.
46개가 1초 이상 어긋나 있었다 — 오차즈케 −3초, 매운 알 구간 통째로 −10초,
"도와주지 마" −12초. 앞부분은 멀쩡해 보여서 눈으로는 못 잡는다.

**표준 절차 (`scripts/align/` 참고):**
1. `pieces.py` — 조각 실제 길이로 원본→출력 매핑 (17번)
2. `chunk_transcribe.py` — 컷 완료 본편을 **90초/8초 겹침으로 쪼개 전사**.
   긴 파일을 한 번에 전사하면 대사가 있는 구간을 통째로 건너뛴다(실제 2곳 발생).
3. `align3.py` — **단어 타임스탬프**에 자막을 **순차(monotonic)** 정렬.
   세그먼트 단위는 whisper 문장 끊기에 좌우돼 오탐이 나고,
   순차가 아니면 같은 문장이 여러 번 나올 때 엉뚱한 쪽에 붙는다.

**검증은 기계로 한다:** 각 자막이 ±2.5초 안에서 음성과 일치하는지 되짚어 확인.
목표 평균오차 0.1초 이내(260815 최종 0.092초, 중앙값 0초).
불일치는 하나씩 눈으로 본다 — **컷돼서 영상에 없는데 자막만 남은 경우**가 2건 있었다.
검증은 반드시 **음악·효과음 없는 본편**으로 — 최종본으로 하면 whisper가 잘못 들어 오탐이 는다.

### 18-1. 겹치는 자막은 '뒤를 미루지' 말고 '앞을 줄인다'
260815에서 슬기가 "앞부분에도 자막 밀리는 게 있다"고 재지적. 측정해보니
**정확히 -0.52초가 반복**됐고, 원인은 겹침 처리 로직이었다.
자막 최소 길이를 0.8초로 두고 겹치면 뒤 자막을 `앞끝 + 0.02`로 미뤘는데,
"그래도?" → "그럼 구경만 할 거야?" 처럼 대사가 0.3초 간격으로 오가는 구간에서
**뒤 자막이 매번 0.5초씩 늦게 떠서** 밀리는 것처럼 보였다(36개 발생).

```python
# 나쁨 — 뒤를 미룬다
if s < prev_end: s = prev_end + 0.02
# 좋음 — 앞을 줄인다
if s < prev_end:
    prev_end = max(prev_start + 0.28, s - 0.04)
```
최소 길이도 0.8초 → **0.50초**로 낮춘다(빠른 대화에서 뒤를 밀지 않게).
수정 후: 평균 오차 -0.083초 → **-0.000초**, 늦게 뜬 자막 36개 → **0개**.

**검증은 ±2.5초가 아니라 ±6초 창으로** 한다 — 좁은 창으로 재면
0.5초씩 밀린 것도 "일치"로 세어 문제를 못 잡는다. 오차의 **부호 분포**도 같이 본다
(한쪽으로 쏠려 있으면 로직 버그다).

### 20-3. 선명도 지표의 두 함정 — 반드시 고쳐서 쓴다 (260823 실패)
슬기: "웃는 얼굴인데 약간 못생기게 나온사진 캡쳐야 흔들리지 않은 사진으로 해주고 특히 메인사진이면"
흔들린 프레임을 메인으로 골랐던 원인이 **지표 자체의 결함 두 개**였다.

**함정 1 — 얼굴 검출이 어른을 잡는다.**
`max(faces, key=area)`는 아이+어른 투샷에서 항상 **어른 얼굴**을 고른다.
아이 기준으로 재려면 면적이 일정 이상인 얼굴 중 **작은 쪽**을 쓴다:
```python
cand = [f for f in faces if f[2]*f[3]/(W*H) >= 0.020]
fx,fy,fw,fh = min(cand, key=lambda f: f[2]*f[3])[:4]
```

**함정 2 — Laplacian 분산은 얼굴 크기에 좌우된다.**
얼굴 영역을 그대로 재면 **작고 또렷한 얼굴이 크고 살짝 흔들린 얼굴보다 무조건 높게** 나온다.
실제로 클로즈업 웃는 컷이 8점, 멀리 있는 옆모습이 190점으로 나왔다.
반드시 **얼굴을 고정 크기(200x200)로 리사이즈한 뒤** 잰다:
```python
g = cv2.cvtColor(cv2.resize(face, (200,200)), cv2.COLOR_BGR2GRAY)
sharp = cv2.Laplacian(g, cv2.CV_64F).var()
```
정규화 후 재측정: 잘못 고른 메인 89점 vs 새로 고른 메인 342점(4배 차이).
**메인은 정규화 선명도 250 이상**을 기준으로 삼는다.

**표정·가림 최종 확인:** 점수만 믿지 말고 상위 후보를 얼굴 크롭 시트로 만들어 눈으로 고른다.
음식·빨대·컵이 입을 가로지르면 표정이 아무리 좋아도 탈락시키거나, 소품이
프레임 밖으로 나가도록 크롭한다(260815: 우유팩은 빼고 빨대 끝만 남김).
구현: `scripts/pick2.py`

## 21. 컷을 수정하면 자막 정렬이 통째로 깨진다 (260824 실측)

키프 리스트 한 구간을 12초→3초로 줄였더니, 그 뒤 모든 자막이 출력 타임라인에서
9초씩 어긋났다. 이 상태로 `align_body.py`를 그냥 다시 돌리면 **정렬 창(win=6.0초)을
넘어서기 때문에 137개 중 82개가 매칭 실패**한다. 실패한 자막은 옛 시각을 그대로
유지하므로 결과가 더 나빠진다.

**정해진 복구 순서 (3단계)**

1. **1패스 — 넓은 창** `run(win=25.0, thresh=0.50)`
   컷 이동량보다 넉넉히 큰 창으로 대부분(여기선 116/137)을 다시 잡는다.
2. **2패스 — 좁은 창** `run(win=6.0, thresh=0.52)`
   1패스 결과를 입력으로 다시 돌려 정밀도를 회복한다.
3. **3패스 — 미매칭분 좌표 역산**
   전사에 안 잡히는 자막(짧은 감탄사 "박수!"·"봐봐", 반향이 큰 실내, 통화 잡음)은
   1·2패스로 절대 안 잡힌다. 이건 정렬로 풀지 말고 **keep 리스트의 옛/새 버전을
   둘 다 만들어 `옛 출력시각 → 원본시각 → 새 출력시각`으로 산술 재매핑**한다.

```python
def cum(segs):
    outs, c = [], 0.0
    for lo, hi, *_ in segs:
        outs.append((c, lo, hi)); c += hi - lo
    return outs, c

O, _ = cum(old_merged); N, _ = cum(new_merged)

def old2new(t):
    src = None
    for c, lo, hi in O:                       # 옛 출력 → 원본
        if c <= t < c + (hi - lo): src = lo + (t - c); break
    if src is None: return None
    for c, lo, hi in N:                       # 원본 → 새 출력
        if lo <= src < hi: return c + (src - lo)
    return None                               # 잘려나간 구간 → 자막 삭제
```

`old_merged`는 현재 keep.py에서 **바뀐 구간만 되돌려** 만들면 된다.
반환이 None이면 그 자막은 잘린 구간에 있었던 것이므로 **삭제**한다.

검증은 재정렬 결과가 아니라 **본편 전사와 직접 대조**해서 한다.
목표: 평균 오차 ±0.10초 이내, 중앙값 0초, 판정 대상의 95% 이상이 ±0.25초 이내.

  (한글의 56%, #EEE8DC). 블록 **바닥을 y=1545에 고정**(줄 수가 늘어도 UI에 안 걸림).
  훅과는 다른 폰트를 쓴다. 영문은 축어역 금지 — 짧은 구어로, 문화어는 풀어서
  (에디슨 젓가락→training chopsticks, 이놈→scold). 사전 `scripts/reels/trans.py`

### 인스타 표시영역 — 글자는 y 285~1590 안에만
프로필 그리드 3:4(240~1680) ∩ 홈피드 4:5(285~1635) ∩ 릴스 UI(200~1590) = **285~1590**.
이 교집합을 벗어난 글자는 어딘가에서 반드시 잘린다.

**검정배경+상단 타이틀카드 방식은 이것 때문에 버렸다** — 타이틀 첫 줄이 프로필 그리드에서
통째로 사라졌다. 풀블리드는 타일 전체가 영상이라 손실 0이고, **커버를 훅이 떠 있는
앞 5초에서 고르면 그리드 타일에도 제목이 박힌다**(타이틀카드의 유일한 장점이 상쇄됨).

### 컷 단위 얼굴추적 크롭
화자를 실시간으로 좇으면 화면이 흔들린다. **컷마다 위치를 정하고 컷 안에서만 완만히 이동**한다.
- 컷 검출 : `select='gt(scene,0.42)',showinfo`
- 컷당 0.8초 간격 샘플 → mediapipe BlazeFace → 중앙값 3점 → EMA 0.46 → 속도제한 155px/s
- 얼굴이 여럿이면 **작은 얼굴(아이)에 가중치 2.4배**, 전부 창 안에 들어오면 전체 중심
- **아이 얼굴이 가장자리 90px 안쪽에 있도록 하드 제약** (이거 없으면 아이가 프레임에 걸친다)
- ffmpeg 적용은 중첩 if 없이 **램프 합**으로:
  `x = x0 + Σ (dx_i)*max(0,min(1,(t-t_i)/dt_i))`
- 얼굴 검출 실패 시 살색(YCrCb)+디테일 가중 중심으로 폴백. Haar는 옆얼굴을 놓치니 쓰지 말 것.

### 소스는 자막 안 박힌 것으로
완성본에서 크롭하면 번인된 자막 양쪽이 잘려나간다. **컷편집본(자막 없는 것)에서 다시 자르고
자막은 SRT 기준으로 9:16용으로 새로 그린다.**

- Pretendard = "무심하다"(본문용 중립체) / 주아·도현·블랙한산스 = "올드하다"(2014~2016)

## 26. 완성본에서 원본 되찾기 (자막 없는 소스가 필요할 때)

릴스는 자막이 안 박힌 소스에서 잘라야 하는데, 조립 타임라인(keep.py 등)이 없으면
**원본 클립 지문 인덱스**로 되찾는다. `scripts/reels/{fpindex.py, match.py, map2.py}`

### 절차
1. `fpindex.py` — 원본 클립 전체를 1fps · 32×18 그레이로 인덱싱 (300클립 ≈ 13000프레임, 6MB)
2. `map2.map_segment()` — 완성본 구간을 **1초 단위로 각각** 인덱스와 대조 →
   (클립, 오프셋)이 같은 연속 구간끼리 그룹핑
3. `map2.refine()` — 조각별로 ±2초를 0.2초 간격 슬라이딩해 서브초 오프셋 확정

### 반드시 지킬 것
- **컷 검출(scene)에 의존하지 말 것.** 비슷한 화면끼리 이어붙인 구간은 장면전환으로
  안 잡혀서 클립 경계를 놓친다. 실제로 한 구간이 3개 클립에 걸쳐 있었다.
- **조각 시작 = 오프셋 + 구간내위치**(`off + a`). 오프셋만 `-ss`에 넣으면 내용이 통째로 밀린다.
  (`map2`의 off는 "구간 상대시각 → 클립시각" 변환상수다)
- 지문은 **번인 영역을 빼고** 비교한다(32×18 중 행 3~13). 하단 자막·좌상단 배지 제외.
- **매칭 품질 판정** : 지문거리 <20 정상, 20~30 색보정 차이일 수 있으니 눈으로 확인,
  >30 이면 대개 오매칭. 머리·꼬리의 짧고(<2.5초) 나쁜(>25) 조각은 버리고 이웃을 늘린다.
- **세로 촬영분은 매칭이 안 된다** — 완성본에서 블러패드된 프레임과 원본 세로 프레임의
  지문이 완전히 다르기 때문. 그 구간은 시작점을 옮기거나 따로 처리한다.

## 27. 성능 — 프레임마다 ffmpeg를 띄우지 말 것

얼굴추적 샘플링을 프레임당 `ffmpeg -ss` 로 하면 편당 60번 프로세스를 띄운다(2~3분).
**조각을 한 번에 디코드해 메모리에서 처리**하면 45초로 준다.
```
ffmpeg -ss A -t D -i src -vf fps=R,scale=960:-2 -pix_fmt bgr24 -f rawvideo -
→ np.frombuffer(...).reshape(n, H, 960, 3)
```
지문 비교도 마찬가지 — `fp_range()` 로 구간을 통째로 뽑아 numpy로 비교한다.

## 28. 외장 SSD 동시 접근 주의

빌드가 SSD를 읽는 중에 **다른 ffmpeg로 같은 SSD를 읽으면 출력이 깨진다.**
h264 `Invalid NAL unit size` 가 수천 줄 나오는데 **ffmpeg는 exit 0으로 끝나고 파일 크기도
정상**이라 눈치채기 어렵다. 반드시 출력마다 디코드 검증을 건다:
```
ffmpeg -v error -i out.mp4 -f null -    # returncode 0 이고 stderr 비어야 정상
```
빌드 중에는 확인용 프레임 추출도 하지 말 것. 검증은 빌드가 끝난 뒤에.

또한 검증 스크립트가 **실패한 프레임 대신 이전 임시파일을 읽는 사고**가 있었다.
임시파일은 매번 고유 경로를 쓰고, ffmpeg returncode를 반드시 확인한다.
